# Android build — Capacitor (Gradle)

The Android app is the Vite web bundle (`client/dist`) packaged into a native
WebView shell by **Capacitor 8**. The Gradle project is a committed source
artifact at repo-root `android/` (not generated at build time). This replaced
the Bubblewrap Trusted Web Activity on 2026-09-13 (Capacitor migration Stage 6);
`docs/ARCHITECTURE.md` "Capacitor migration" has the full picture.

## What's in the repo

| Path | Purpose | Committed? |
| --- | --- | --- |
| `client/capacitor.config.ts` | Capacitor config — `appId app.web.oneonone`, `webDir dist`, `android.path ../android`. | yes |
| `android/` | The Gradle project (`app/`, wrapper, `AndroidManifest.xml`, `res/`, native plugins in `app/src/main/java/app/web/oneonone/`). | yes |
| `android/app/build.gradle` | `signingConfigs.release` wired to `keystore.properties` (guarded — absent means unsigned release). `versionCode`/`versionName` come from `-PappVersionCode` / `-PappVersionName`, defaulting to `1` / `1.0.0`. | yes |
| `android/keystore.properties.example` | Template for the signing file. | yes |
| `.github/workflows/android-build.yml` | Builds + signs the `.aab` and `.apk` on a GitHub runner and asserts the signer fingerprint. | yes |
| `android/keystore.properties`, `android/android.keystore` | Signing material. **Never committed** — CI writes them from secrets. | no |
| `android/app/google-services.json` | Firebase (FCM) config for `app.web.oneonone`. Gitignored — CI writes it from a secret; without it the build still passes but push is disabled. | no |
| `android/app/src/main/assets/public`, `android/capacitor-cordova-android-plugins`, `capacitor.config.json` | Generated by `npx cap sync android`. | no |
| `client/public/.well-known/assetlinks.json` | **Dormant.** Digital Asset Links was a TWA requirement; the Capacitor app has no App Links intent filter, so nothing reads it. Kept because it already carries the upload-key SHA-256 and would be needed again if App Links are added. | yes |

## Signing identity — one key, never regenerated

The **upload key** is `android/android.keystore`, alias **`oneonone-upload`**:

| | Fingerprint |
| --- | --- |
| SHA-1 | `36:A9:69:D6:10:20:E0:7E:33:79:9F:0C:04:CE:F5:1A:63:BB:90:C6` |
| SHA-256 | `4B:0E:07:42:D4:9B:3A:30:4F:43:C1:3F:44:1E:62:06:91:CE:98:A8:A9:D6:09:5F:E0:71:0F:30:74:C6:74:57` |

This key is registered with **Play App Signing** (as the upload key) and with the
**Google OAuth Android client** (`one-on-one-508202`, package `app.web.oneonone`)
that native Google sign-in depends on. A build signed with any other key is
rejected by Play and fails sign-in with `[16] Account reauth failed`.

The keystore exists only as the `ANDROID_KEYSTORE_BASE64` repo secret (plus the
user's offline backup). The CI workflow **never generates a keystore** and fails
if any secret is missing. Every run asserts the SHA-1 above twice — on the
restored keystore before building, and on the produced `.aab` + `.apk` after.

## Repo secrets (Settings → Secrets and variables → Actions)

| Secret | Value |
| --- | --- |
| `ANDROID_KEYSTORE_BASE64` | `base64 -w0 android.keystore` (unchanged since the TWA era) |
| `ANDROID_KEYSTORE_PASSWORD` | store password (unchanged) |
| `ANDROID_KEY_PASSWORD` | `oneonone-upload` key password (unchanged) |
| `GOOGLE_SERVICES_JSON_BASE64` | `base64 -w0 android/app/google-services.json` (from the Firebase console, Android app `app.web.oneonone`) |
| `VITE_SUPABASE_URL` | same as `client/.env` |
| `VITE_SUPABASE_ANON_KEY` | same as `client/.env` (public anon key) |

`VITE_API_URL` is committed in `client/.env.production` and needs no secret.

## Path A — build in CI (recommended)

Actions tab → **android-build** → *Run workflow*. Inputs: `versionCode`
(integer, must strictly increase per Play upload) and `versionName`.

Steps the workflow runs: `npm ci` + `npm run build` in `client/` (Node 24) →
`npx cap sync android` → write `keystore.properties` / `android.keystore` /
`google-services.json` from secrets → `keytool -list` SHA-1 assertion →
`./gradlew bundleRelease assembleRelease` (Temurin JDK 21) → signer assertion
on both outputs (`keytool -printcert -jarfile` for the AAB, `apksigner
verify --print-certs` for the APK) → upload the `android-release` artifact
(`app-release.aab` + `app-release.apk`) → scrub the secret files.

Upload `app-release.aab` to Play. `app-release.apk` is for sideloading onto a
device (`adb install`); it is signed with the same upload key, so native Google
sign-in works on it.

## Path B — build locally

Needs JDK 21 (Android Studio's bundled JBR works: set `JAVA_HOME` to
`C:\Program Files\Android\Android Studio\jbr`) and the Android SDK
(`android/local.properties` → `sdk.dir`).

```bash
cd client
npm ci
npm run build              # needs client/.env with VITE_SUPABASE_URL / _ANON_KEY
npx cap sync android
cd ../android
# optional, for a signed build: cp keystore.properties.example keystore.properties
#   and fill in the passwords + put android.keystore beside it
./gradlew bundleRelease assembleRelease -PappVersionCode=1 -PappVersionName=1.0.0
```

Outputs: `android/app/build/outputs/bundle/release/app-release.aab`,
`android/app/build/outputs/apk/release/app-release.apk`. Without
`keystore.properties` both are **unsigned** (fine for checking the build,
useless for Play or for Google sign-in).

For the day-to-day dev loop use Android Studio's Run button /
`./gradlew installDebug` — the debug variant is signed with
`~/.android/debug.keystore`, whose SHA-1 is registered as a second OAuth
Android client (see `docs/PROGRESS.md`, Stage 2 bugfix).

## After the first Play upload — register the Play App Signing key

Play re-signs the distributed app with its **own** key. Two things to do once,
after the first `.aab` upload:

1. Play Console → **App integrity** → **App signing key certificate** → copy the
   **SHA-1**.
2. Google Cloud Console (project `one-on-one-508202`) → Credentials → create
   another **Android** OAuth client: package `app.web.oneonone`, that SHA-1.
   Additive — keep the upload-key and debug-key clients. Without this, native
   Google sign-in fails on every Play-installed build.

(The SHA-256 from the same screen would go into `assetlinks.json` only if App
Links are ever added — not needed today.)
